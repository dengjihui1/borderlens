# BorderLens 交付边界与执行计划

统筹日期：2026-10-22。以当前代码和可检查的发布为准，不把历史阶段编号或目录规模当作完成度。

## 1. 本版交付定义

本版定位为**官方证据支持的只读旅行证件规则查询与逐段自查工具**。交付一个能实际使用的闭环，不以清空 REVIEW 或自动通关为完成标准。

- `/policies` 是完整种子库的可用查询入口：实际证件（含签发地）、目的地、目的、交通方式、结论状态。
- `/coverage` 展示目录、来源和逐组有效性，不把找到网址算成规则覆盖。
- `/` 接入全部 147 条种子规则，支持 1–8 段、每段实际证件、日期、交通、用途、口岸备注及入境依据，输出规则、条件、自查待办和打印清单。
- `/demo` 保存早期独立演示并继续隐藏过期历史结论；首页不再依赖旧规则日期。
- 空侧转机、未知入境、居民/公民返境不套用访客规则；返程和返程转机必须显式录入。现阶段不自动判断第三国资格、实际口岸、出境、累计停留或个人通关准备，不输出全程 READY。
- 不收集证件号码、照片、地址、完整出生日期；不申请、付款、上传或提交材料。

## 3. 统一口径

截至 2026-10-22 UTC Phase 85：147 条结构化记录、127 个来源，135 条证据仍在核验窗口内，7 条历史到期、5 条明确证据问题。

135 条当前有效规则中另有 3 条 `manual_review`，所以规则查询显示 **132 条当前可展示结论 + 15 条 REVIEW**（7 条到期、5 条证据待复核、3 条个体条件待核）。覆盖页的 **135 当前有效 + 12 到期/证据待复核** 统计的是证据时效，二者分母和总数一致，但不能混叫“135 个自动通行结论”。

接入查询时额外复核新西兰当前官方正文，将港澳两条的 90 天纠正为 3 个日历月。该修正是期限单位纠错，不新增覆盖或自动放行资格。

每条记录继续保留全部适用条件。免签、电子许可、电子签申请和落地签不是同一种待遇；规则当前有效也不代表个人符合全部条件或保证入境。

## 4. 后续执行顺序

1. 先验收可用闭环：真实浏览器载入示例、生成、多证件切换、添加/移除、编辑旧结果、未来日期降级、自查与窄屏显示。阶段发布不掺入未核实政策变化。
2. 继续用 `npm run data:review` 获得实时队列；先处理有新官方证据的冲突/缺口，再按来源组复核历史规则。访问受阻或无新增证据时记录后换下一组，不重复无效请求、也不机械续期。
3. 每批记录官方 URL、原文定位、时间、证件和用途、期限口径、冲突与访问限制；更新必要回归测试。新增个人资格自动判断前先结构化决定性条件；不能把自然语言条件当作已经满足。
4. 每个可检查阶段独立运行质量门禁、commit、push、私有发布；只维护一个当前最终包，旧包可恢复归档。阶段完成只指该范围验收，不声称全库或全部产品愿景完成。

## 5. 何时可以说完成

“规则查询与逐段自查本版交付”须有上述 P0 代码、浏览器验收和私有发布；“某条路线已核验”须有当前官方证据；“全自动个人资格预检”仍须完成 P1 结构化条件。不得说“全球规则全部完成”。活政策持续变动，复核队列是长期维护工作，不会被一次性清零承诺替代。
