# BorderLens 交付边界与执行计划

统筹日期：2026-10-21。以当前代码和可检查的发布为准，不把历史阶段编号或目录规模当作完成度。

## 1. 本版交付定义

本版定位为**官方证据支持的只读旅行证件规则查询工具**，不是自动签证办理或保证通关的系统。

- `/policies` 是完整种子库的可用查询入口：实际证件（含签发地）、目的地、目的、交通方式、结论状态。
- `/coverage` 展示目录、来源和逐组有效性，不把找到网址算成规则覆盖。
- `/` 保留早期逐段路线演示，并明确指出其独立核验日期与覆盖范围。它没有自动接通所有数据库路线，不能被宣传为全球行程引擎。
- 不收集证件号码、照片、地址、完整出生日期；不申请、付款、上传或提交材料。

## 3. 统一口径

截至 2026-10-21 Phase 70：143 条结构化记录，85 条证据仍在核验窗口内，55 条历史到期、3 条明确证据问题。

85 条有效证据中另有 1 条 `manual_review`，所以规则查询显示 **84 条当前可展示结论 + 59 条 REVIEW**。覆盖页的 **85 当前有效 + 58 到期/证据待复核** 统计的是证据时效，二者分母和总数一致，但不能混叫“85 个自动通行结论”。

接入查询时额外复核新西兰当前官方正文，将港澳两条的 90 天纠正为 3 个日历月。该修正是期限单位纠错，不新增覆盖或自动放行资格。

每条记录继续保留全部适用条件。免签、电子许可、电子签申请和落地签不是同一种待遇；规则当前有效也不代表个人符合全部条件或保证入境。

## 4. 后续执行顺序

1. 用 `npm run data:review` 获得实时队列，不维护另一份手写国家待办清单。先解决 3 条证据问题，再按到期日和官方来源组处理历史规则；单一来源组内可以并行读取，禁止机械续期。
2. 每批记录官方 URL、原文定位、时间、证件和用途、期限口径、冲突与访问限制；更新必要回归测试。
3. 建立生产逐段引擎前先结构化决定性条件；不能把自然语言条件当作已经满足。沿用过期成员映射、把年累计当单次、把日历月换成固定天数均不允许。
4. 每个可检查阶段独立运行质量门禁、commit、push、私有发布；只维护一个当前最终包，旧包可恢复归档。

## 5. 何时可以说完成

“查询工具本版交付”须有上述 P0 的代码与验收；“某条路线已核验”须有当前官方证据；“完整逐段预检”还须完成 P1 行程引擎；不得说“全球规则全部完成”。活政策持续变动，复核队列是长期维护工作，不会被一次性清零承诺替代。
